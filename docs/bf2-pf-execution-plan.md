## 一、路径模型落盘（P1，本地线）

**目标**：把三层机制的"骨架"固化进配置文件——每条路径经过哪些组件、每个组件挂哪些计数器、每个计数器用什么公式。

工作项：

1. `configs/path_table.conf`：8 条路径（P1–P8）的顶点序列；每顶点挂的计数器清单；每计数器字段：类别（频率/压力/忙闲/错误/效率）、公式族（跨度/容量/AF/EMPTY/丢包/miss）、证据层级、锚点来源、是否共享组件。
2. 共享组件 M1 拆分：MSS、tilenet、L3 等被多路径共用——按各路径入口流量比例分摊，映射与比例由 `tools/path_data.py` 维护，并用流量守恒校验（Σ 分摊 = 总量）。
3. 与既有事实对齐：路径顶点序列须与 XNova 四路径核实、师兄 Arm 数据流图、论文六类路径口径一致，请用户过目确认。

产出物：`configs/path_table.conf`、`tools/path_data.py`（更新）。
验收：52 条论文计数器全部归位或显式标注缺口；守恒校验通过；用户确认路径序列。

## 二、锚点表（P1.5，本地为主）

**目标**：给第一层的每把尺子装上刻度。

工作项：

1. λ_idle 提取：从 G 系列 pre-idle 5 秒窗口按计数器取均值，生成 `configs/anchor_idle.conf`（脚本：`tools/extract_anchors.py`，本地跑 G 系列 CSV）。
2. λ_sat 初值回填：从 bench p1–p7 CSV 按基准取平台段最大值，生成 `configs/anchor_sat.conf` 初版——**先跑通机制，精度后续再提升**。
3. 缺口清单：列出无任何基准覆盖的计数器，逐一指定兜底策略（容量法 λ/C 或 miss 率公式）。
4. 精确饱和标定操作单：`docs/saturation-calibration-opsheet.md`（membench→内存面、stress-ng→L2/核面、iperf3→网口面、fio→eMMC 面），设备执行放在第六部分。

产出物：两个 anchor 配置、缺口清单、标定操作单。
验收：每类资源至少一个饱和参考；缺口全部有兜底公式。

## 三、分析器实现（P2，本地线）

**目标**：三层索引的计算引擎。

工作项：

1. `tools/analyze_bottleneck.py`：输入 CSV + path_table.conf + 两个 anchor 配置 → 逐窗口输出：n_c（六种公式+clamp）、v_j/m_j（max+mean、证据标签）、L_p（路径 Σ+伴随量）、仲裁警示（同顶点跨层级矛盾）、退化统计（argmax 层级分布）。
2. 证据分级与可用性门槛落地：压力>忙闲>频率>效率；未证实计数器（MSS_NO_CREDIT 等）只旁路不仲裁。
3. 自检：HNF×xz 手算对照（n_A72=0.34）；空 CSV/缺失计数器容错。代码 ASCII-only、注释英文（既有工程约束）。

产出物：`tools/analyze_bottleneck.py` + 手算对照测试。
验收：公式输出与手算一致；G 系列 CSV 全量跑通无异常。

## 四、历史回放验证（P2 验证·回放关，本地线）

**目标**：用既有实验的独立判读结论检验三层索引的排序正确性——零设备依赖的第一轮验证。

工作项：

1. 空载关：G 系列空闲段回放，所有 n_c≈0、L_p≈0。
2. 回放关：xz/BFS→CR 路径最忙、Redis→NAD、iperf NHD→P5——三层索引排序须与这些既有判读一致；G3/G7/N2 涓流负载→全部 L_p 低位。
3. 退化检查：argmax 层级随负载类型应有变化；若某计数器恒为 argmax，判定"真决定性瓶颈"或"锚点标定错误"。
4. 结论落盘：`docs/validation-replay.md`（一致项、不一致项、回查结论）。

产出物：验证报告（可选配图）。
验收：与既有判读一致率达标；不一致项有归因结论（回查锚点/映射并修正后重跑）。

## 五、前置事实补证（P0 收尾，设备线，与四并行）

**目标**：把三个悬而未决的硬件事实钉死，它们是模型证据链的地基。

工作项：

1. MSS_NO_CREDIT 探针实验：执行既有操作单 `docs/counter-failure-probe-opsheet.md`，判读"它到底会不会动"→ 决定压力类证据能否进入仲裁。
2. P1 规则计数补验：collect_pipe.sh 已修 grep 引号坑，设备上重验规则计数（9/15 遗留）。
3. M2 部署：Task #30——部署 `tools/collect_pipe.sh` + 执行 §5.5 验收操作单。
4. paper52.conf 与路径表对齐复核（52 条论文计数器逐一映射到顶点）。
5. 每个交付完成后：git 入库与否请用户定夺（fig/tools/docs 未经批准不提交）。

产出物：探针判读记录、部署验收记录。
验收：压力类证据可用性裁定明确；M2 验收通过。

## 六、设备实测验证（P2 验证·因果关，设备线）

**目标**：在真机上证明压力指数与饱和逼近的因果对应，产出论文数据。

工作项：

1. 精确饱和标定：执行第二部分交付的标定操作单，替换 anchor_sat 初值。
2. 定向应力：打满内存/L2/网口各一次，对应路径 L_p 应显著最大（因果关）。
3. 真实负载复测：7 应用（xz/BFS/BS/Redis 等）完整采集，判读并检查多次运行的一致性。
4. 结果判读落盘：与第四部分同样格式的验证记录。

产出物：标定数据、实测判读报告。
验收：应力-路径对应关系成立；真实负载判读稳定（多次运行一致）。

## 七、论文化（P3，本地线）

**目标**：把建模与验证结果落进论文。

工作项：

1. 模型章节素材：以手册为蓝本改写为论文语言（三层机制、可比性论证、诚实声明）——**无 AI 痕迹、中英双语**（既有硬性要求）。
2. 图表：每应用每路径 L_p 排行图（沿用 gnuplot 既有样式与配色）；覆盖率表。
3. CRITICAL 项落实：IB bypass 非 I/O 专属须标注、L_p 非队长声明、背压覆盖约半数转发点的披露。
4. 论文中位置与用户论文结构对齐（用户定）。

产出物：论文素材文档 + 图。
验收：用户审核通过。

## 八、明确不做（守范围，防止蔓延）

- 顶点级定位（哪一环堵）——延迟类观测缺失，结构性偏差。
- 探针 Q_wait、W 标定实验——留未来。
- tilenet 48 DIAG 探针、STALL_BACKEND 0x23——留未来。
- 上述作为"未来工作"写入论文展望，不在本计划内执行。

## 风险与回退

| 风险 | 表现 | 回退 |
|---|---|---|
| λ_sat 标定打不满 | 跨度归一化普遍偏高 | 换基准/容量法 λ/C 兜底 |
| 回放不一致 | 排序与既有判读冲突 | 回查锚点/映射，修正后重跑，记录归因 |
| MSS_NO_CREDIT 恒 0 | 压力类证据缺位 | 可用性门槛已备：压力类旁路，忙闲类为主证据 |
| 设备时间不确定 | 设备线拖期 | 本地线（一~四、七）不阻塞，回放验证先行 |
