# PRISM 模型总览（Model Overview）

> **PRISM** = **PR**essure **I**ndex **S**ummation **M**odel（压力指数累加模型）
> 命名寓意：棱镜（prism）把一束白光分解为光谱；PRISM 把一条数据路径的整体繁忙
> 指数分解为各顶点的贡献谱——"Summation"即核心运算 L_p = Σ（沿路径顶点累加）。
>
> 版本：2026-09-22 ｜ 状态：与论文草稿（Task #41）同步 ｜ 维护：docs/ 下的设计文档族

---

## 1. 一句话定位

PRISM 是面向 BlueField-2（BF2）智能网卡的全片数据通道**瓶颈搜索模型**：它把
片内约 52 枚硬件性能计数器的读数逐层归约，先归一化为 [0,1] 的压力指数，再在
**顶点**（观测点）上融合、在**路径**（端到端数据通道）上累加，最后给出三件套
输出——**哪条路径最繁忙**（判决）、**这条路径的繁忙由谁构成**（顶点归因）、
**全片哪个观测点最受压**（全局顶点排序）。

三句口诀：**计数器归一化 → 顶点融合 → 路径累加**；**幅度判大小，方向判一致**；
**只提示、不改判**（所有辅助机制都不干预主判决）。

## 2. 系统全景（数据流）

```
 BF2 设备（Arm 侧）                          本地主机（Windows）
 ┌──────────────────────┐                  ┌───────────────────────────┐
 │ code/bf2-collector   │    tar 回传       │ tools/ 分析工具族          │
 │  └ 硬件计数器 (sysfs) │ ────────────────▶│  1. analyze_bottleneck.py │
 │     · 机制一/二       │   CSV + .phase.  │     （三层索引引擎）        │
 │     · delta 差分      │   log            │  2. prism_search.py       │
 │  bench/ 负载程序      │                  │     （搜索/判决/归因/图）   │
 │ configs/*.conf ───────┤                  │  3. replay_validate.py    │
 │ （52 计数器/锚点/     │                  │     （回放回归门）          │
 │  路径表 与主机同源）   │                  └────────────┬──────────────┘
 └──────────────────────┘                               ▼
                                         报告三件套 + 双面板图 (gnuplot)
                                         └ 自检：A 回放 / B 锚点 / C 归因
                                            / C5 分歧规则 / D 渲染
```

- **设备侧**只做"读硬件、出 CSV"：计数器是单调累积值，采集器按采样间隔做
  **delta 差分**（`本次值 − 上次值`，再除以间隔秒数）得到速率；负载窗口起止由
  同名的 `.phase.log` 标定（负载程序开始/结束时打时间戳）。
- **主机侧**做全部建模与判决：设备 CSV 是唯一输入，模型、锚点、路径表全部是
  `configs/` 下的静态配置，两测同源（设备与主机共享同一套 configs）。

## 4. 核心概念词典

> 每个术语首次出现即解释，按"从底向上"排列。

| 术语 | 定义 |
| --- | --- |
| **计数器（counter）** | 片内硬件观测点（tile/HNF、tilenet、L3、TRIO、pcie 等），读数单调累积，经 delta 差分得速率 |
| **锚点（anchor）** | 每枚计数器的两个参照：空载参照（idle，静默基线）与饱和参照（sat，满负荷读数），用于归一化 |
| **归一化（n）** | 把速率映射到 [0,1] 的"压力指数"：0=静默，1=贴近饱和参照。六族公式见 §5.2 |
| **顶点（vertex）** | 数据通道上的一个**观测点**（如 arm=Arm 面 representor、l3=三级缓存、pcie0=主机面链路、hnf=核内 home node）。一个顶点可挂多枚计数器 |
| **融合（fusion）** | 顶点值 v = 该顶点各计数器归一化读数的**最大值**（max 融合），并附伴随均值与"哪个计数器登顶"的来源标签 |
| **路径（path）** | 端到端数据通道，共七条：**cr**（核读写请求）、**ih**（DMA 至主机/DDR）、**ib**（旁路 Home Node 的直读）、**wb**（脏行写回）、**nad**（网→Arm 终接）、**nhd**（网→主机直通）、**tx**（Arm→网） |
| **L_p** | 路径繁忙指数：沿该路径顶点 v 的累加和。是**归一化压力指数，不是队列长度** |
| **M1 份额（share）** | 共享顶点（同属多条路径）的流量按各路径入口速率比例拆分；`SHARE_EPS` 地板防止噪声入口独吞份额 |
| **行（row）** | 一次采样间隔（1 秒）内的全部计数器读数。判决的原子证据单位 |
| **票（wins）** | 一行的方向证据：该行 L_p 最高的路径得 1 票（低于 `VOTE_FLOOR` 的行弃权） |
| **幅度判据** | 窗口中位数 L_p：≥0.2 为"忙"，<0.2 为"静" |
| **方向判据** | 票数过半（>50% 行）为"方向一致" |
| **三值判决** | **dominant**（忙且方向一致）/ **multi**（忙但方向分散，多路径并发）/ **low**（静，无繁忙路径） |
| **归因（attribution）** | 胜者路径内各顶点的**贡献 c = v × M1 份额**的行均值排名（全支撑口径） |
| **全支撑口径** | 顶点在某行不可观测时按 0.0 计入该行，保证"各行贡献之和 == 该行 L_p"精确成立（对账口径） |
| **观测行口径** | 只在顶点有读数的行上取均值（全局顶点排序用；从不触发的顶点没有读数，补 0 会把盲区伪造成"不重要"） |
| **稳定性（stability）** | 顶点在本路径行内登顶的次数 / 有登顶者的行数 |
| **flow** | 全局排序中"收到该顶点最大平均贡献的路径" |
| **分歧提示（divergence）** | N1：全局头名的 flow 不在胜者路径上；N2：全局头名读数严格高于胜者路径头号贡献。只提示、不改判 |
| **空载门（idle gate）** | 每个会话的空载窗口 L_p 必须近零，否则该会话数据判为污染 |
| **SAT-SUSPECT** | 顶点长期贴近下界锚点读满 n≈1 时的标注：参照值可能取自负载自身观测下界，读数上限失真，需谨慎判读 |
| **盲点旁证** | 无计数器的四类盲点（L3 内部队列、PCIe TLR、Arm 软件队列、eSwitch 内部队列）由上下游计数旁证推断，输出显式标注 |
| **证据层级（tier）** | 六族计数器的仲裁层级（仅用于来源标注，不参与权重）：1 压力(af/empty) > 2 繁忙(span/cap) > 3 错误(drops) > 4 效率(miss) |

### 计数器方向约定（判读必须记住）

| 计数器 | 方向语义 |
| --- | --- |
| `pcie0_tx` | 卡 → 主机（主机面链路下行投递） |
| `pcie1_rx` | 主机 → Arm 子系统（Arm 面接收） |
| `en3f1_tx` | eSwitch → SF = Arm **入口**方向 |
| `en3f1_rx` | Arm → 交换机 = Arm 出口方向 |
| `pf1hpf_tx` | 交换机 → 主机（主机接收侧） |
| `pf1hpf_rx` | 主机发送侧 |

## 5. 设计原理

### 5.1 三层索引机制（核心创新）

借鉴 PathFinder 的 ΣQ/操作分析法与 USE/DCTCP/MPKI/DCGM 的归一化思想，
把"哪一级堵了"的搜索压缩成三次归约：

```
第 1 层：全量计数器 → 归一化        n_c = f(rate; anchor) ∈ [0,1]
第 2 层：顶点融合                  v_j = max(n_c)（同一观测点多计数器取最受压者）
第 3 层：路径累加                  L_p = Σ v_j × share_j（共享顶点按 M1 份额拆分）
```

设计取舍：**L_p 是归一化压力指数，不是队长**——因为没有队列长度计数器，
"繁忙"以读数相对饱和参照的距离来定义；顶点级因果定位（哪个物理队列堵了）
明确留给未来工作（§7）。

### 5.2 归一化六族（第 1 层）

| 族 | 公式 | 语义 |
| --- | --- | --- |
| `span` | n = clamp((rate − idle)/(sat − idle), 0, 1) | 速率在空载~饱和参照间的线性跨度 |
| `cap` | n = clamp(rate/C, 0, 1) | 速率占链路/带宽容量 C 的比例（运筹利用率律） |
| `af` | n = clamp(af_delta/denom_delta, 0, 1) | 队列近满占比 P(Q≥θ) |
| `empty` | n = clamp(1 − empty_delta/denom_delta, 0, 1) | 缓冲非空占比（1 减空占比） |
| `drops` | 归一化丢包/丢弃计数 | 错误压力 |
| `miss` | 归一化未命中率 | 效率压力 |

`anchor_sat.conf` 中标注 `[unverified]` 的计数器照常计算但**退出仲裁**
（可用性门——探针未证实语义前不给它们发言权）。

### 5.3 顶点融合（第 2 层）

一个观测点挂多枚计数器时取 **max**（该点任一事件维度最受压者代表整体），
并保留三件伴随证据：均值（防单点毛刺误判）、来源标签（哪枚计数器登顶）、
锚点出处（真应力实测 / 观测下界 / 容量表）。max 融合的一个后果——同一顶点
在不同行可能由**不同计数器**登顶（如 mss 顶点交替由 victim_write 与
memory_reads_bypass 登顶），这正是归因与全局排序必须分口径展示的原因。

### 5.4 路径累加与 M1 份额（第 3 层）

路径 L_p 沿其顶点求和；跨路径共享顶点（如 DDR 落点同时属于 cr 与 nad）的
读数按 **M1 机制**拆分：各路径的入口计数器速率之比即份额。两条防护：
`SHARE_EPS`（入口速率低于 1000 B/s 噪声地板时均分，防 epsilon 入口独吞份额）
与 `VOTE_FLOOR`（行 L_p 最高值低于 0.02 的行不投票，防离线噪声票污染方向）。

### 5.5 双判据与三值判决

| | 幅度判据（多忙） | 方向判据（多一致） |
| --- | --- | --- |
| 度量 | 路径 L_p 的窗口中位数 | 行内 L_p 最高者的票数占比 |
| 阈值 | 0.2 判定地板 | 过半数 |
| 产物 | 胜者（magnitude winner） | wins leader（direction evidence） |

两者正交：e4_http_run2 中 nad 幅度 0.257 与 cr 0.238 近平局，方向 8/11 票
才分出胜负——所以双面板图把两判据并置（§6.4）。合成三值判决：

- 中位 <0.2 → **low**（静）
- 中位 ≥0.2 且票数过半 → **dominant**（忙且方向一致）
- 中位 ≥0.2 但无多数票 → **multi**（多路径并发繁忙）

### 5.6 诚实机制（模型的自我怀疑装置）

1. **空载门**：负载窗口之外的行若 L_p 显著非零，会话数据判污染——防"未跑完的
   benchmark 残流"冒充负载信号（曾实际抓到过）；
2. **SAT-SUSPECT**：顶点长期读满 n≈1 且其锚点是观测下界时显式标注——下界锚点
   会把任何真实负载顶到上限，读数失真必须明示；
3. **盲点旁证**：四类无计数器盲点由上下游旁证推断并打印 `[盲点旁证]` 标记，
   模型对观测盲区不虚构压力（openssl 场景即为诚实负例：加密核驻留 L1/L2、
   几乎无网格访存，模型如实判 low）；
4. **口径纪律**：归因用全支撑口径（保证贡献和==行均值 L_p 的对账恒等式），
   全局顶点排序用观测行口径（不补 0，防盲区伪装"不重要"）——两把尺各司其职，
   混用即失真；
5. **只提示、不改判**：分歧提示、SAT-SUSPECT、盲点旁证全部是报告层标注，
   判决规则不引用它们。

## 6. 输出形态

### 6.1 判决报告（stdout）

四件套：① 判决行（verdict + 胜者 + 幅度/方向证据）；② 路径排名
（各路径中位 L_p 降序）；③ 胜者路径归因表（P2.5b：`#1 arm c=0.124 (48.2%)
stable 9/11`，逐顶点贡献、稳定性、来源标签、SAT-SUSPECT 标记，末行打印
贡献和==行均值 L_p 的对账式）；④ 全局顶点排序表（P2.5d：`v=观测行均值 /
obs=观测行数 / flow=最大贡献路径 / owners=所属路径 / 锚点来源`，附分歧提示
结论行——触发时说明、未触发时明示"global peak flows to the X path"）。

### 6.2 双面板路径压力图（P2.5c，gnuplot）

`--plot PREFIX` 渲染一张图两个面板（共享横轴 cr/ih/ib/wb/nad/nhd/tx）：

## 8. 边界声明（写进论文的诚实披露）

1. **顶点级因果定位不在范围**：背压计数器仅覆盖约半数转发点，且无延迟计数器
   ——PRISM 输出的是"路径判决 + 观测覆盖内的顶点压力排序"，不声称"哪个物理
   队列是堵点"；覆盖/时延/因果三个缺口留给未来工作；
2. **锚点两档质量**：14 枚真应力 + 36 枚观测下界，下界锚点顶点读数失真由
   SAT-SUSPECT 机制内建标注；
3. **四类硬件盲点**由上下游旁证，输出显式标注；
4. **Arm→主机出口路径缺失**：路径模型只有核→网 TX 出口；Arm 软件发起、经
   DMA 读入再上行的出口在网口零列可观察的配置下无对应路径；
5. **双口径漂移**：流表规则计数随交换软件重启漂移（早只计 ~23%、现满血
   105%），网络域数据以物理口 sysfs/tc in_hw 与规则计数双口径互校为准；
6. **混合流限制**：NAD 的 DDR 落点与核写请求计数器不可区分，份额拆分为模型
   记账而非物理归属。
